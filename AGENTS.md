# War of Souls 2 — контекст Codex

Отвечай по-русски. Это карта Warcraft III: vJASS/JASS, JassHelper + pjass,
Python 3 и Windows PowerShell. Работай из корня проекта.

## Ориентиры

- MAIN-код: `triggers/**/*.j`; порядок/library — `triggers/README.md`, зависимости —
  `triggers/dependency-manifest.json`, включение — `triggers/trigger-settings.json`.
- Ядро: `triggers/Systems/Systems1.j`, `Systems2.j`, `DmgSys.j`, `CastCheck.j`;
  герои — `triggers/Heroes/`; запуск, пик, магазин и UI — `triggers/WOS_Start/`.
- Редактируемые объекты — `object-data/*.json`; `.object-data-raw/` — служебные
  метаданные для обратной записи, вручную не редактировать.
- TEST — `test_map/`; профиль и пути карты/компилятора — локальный `.vscode/wos-build.json`.

## Читать по задаче

- Импорт/восстановление MAIN: сначала `docs/ai/KNOWLEDGE.md` → CP59 и
  `docs/ui-redesign/RESUME.md` → CP59. Рабочий `war3map.j` может быть новее WCT;
  импортировать WCT как актуальную основу без compiled/source parity нельзя.
  `tools/check_main_source_parity.py` блокирует такой импорт и несогласованную сборку.

- Устройство, зависимости, точка входа неизвестной системы: [ARCHITECTURE](docs/ai/ARCHITECTURE.md).
- Компиляция, тесты, сборка и побочные эффекты команд: [VALIDATION](docs/ai/VALIDATION.md).
- Известный сложный сбой или прежнее решение: [KNOWLEDGE](docs/ai/KNOWLEDGE.md).
- Герои/vJASS/объекты: нужный `.claude/rules/{heroes,jass-systems,object-data-build}.md`;
  Codex читает эти общие справочники явно.
- UI: `.claude/rules/ui-frames.md`, затем заголовки `docs/ui-redesign/RESUME.md`
  (`rg -n '^## ' ...`) и только последний относящийся к задаче этап, а также нужная часть `PLAN.md`.
  Старое вступление может отставать; статус проверяй по исходникам.
  Владельцы и ограничения — разделы `Owners and integration boundaries` / `Root constraints`
  в `docs/ui-redesign/ARCHITECTURE.md`; процесс — `WORKFLOW.md` только для редизайна UI.
- Синхронизация/запись карты — Skill `wos-sync`; создание/перенос героя — `wos-new-hero`.
  Входы — `.agents/skills/`, процедуры общие с Claude.

## Работа и проверки

- Сначала `git status --short`: сохраняй прежние изменения пользователя.
- Для определения функции/rawcode используй `rg -n`, затем нужный диапазон строк.
  Не читай целиком `war3map.j`, WCT/WTG, большие JSON, героев и системы;
  исключай `backups/`, `_build/`, `.build/`, `.vscode/build/`, `map_source/logs/` из широкого поиска.
- После MAIN `.j`: `python tools/check_wos_ui.py` и профильные тесты:
  `python -B -m unittest discover -s tools -p "test_<name>.py"` (существующее имя).
  TEST проверяй своим процессом; MAIN-компиляция его не подтверждает.
- Во всех чатах после любых изменений в проекте обязательно собрать MAIN без запуска и обновить
  `WOS2_MAIN_STABLE.w3x`, сохранив предыдущую версию в бэкап. Это постоянное разрешение
  на проверку, запись и сборку MAIN/STABLE; повторное подтверждение не требуется.
- **РАБОТАТЬ ТОЛЬКО С БЕКАПАМИ (требование пользователя, без исключений).** Перед любой записью в карту
  (TEST/MAIN build, `save`, `check-save`, stage, MPQ Update) и перед правкой `.j`/JSON копировать целиком `.w3x`
  (MAIN и/или `Maps\WoS\Heroes\<Hero>.w3x`) и правимые файлы в `backups/manual/<YYYY-MM-DD_HHMMSS>/` с `README.txt`;
  встроенные бэкапы WCT/WTG не считаются. Проверять WE: `tasklist | grep -i "world editor"` (процесс
  `World Editor.exe`, "worldedit" его не находит); открыт — не собирать, спросить. Путь бэкапа — в отчёте.
  Ротация: в `backups/manual/` не больше 10 папок — после нового бэкапа удалять самые старые сверх 10 (без вопроса).
- **Карта новее проекта → сначала подтянуть в VS Code.** В начале работы и перед каждой правкой/сборкой сравнить
  время `.w3x` и содержимое кода/объектов карты с проектом; если в карте новее или есть чужие отличия — после бэкапа
  export карта → проект (TEST: 1 / `export`), потом править поверх подтянутого.
- Перед `save`, `check-save` и сборкой карты World Editor должен быть закрыт без сохранения.
  Импорт карты в проект может заменять локальные файлы; выбирай направление и MAIN/TEST по запросу.
  Уже данное пользователем разрешение на действие не запрашивай повторно.
- Сохраняй кодировку/окончания строк, не исправляй массово старые комментарии.
  Особые требования TOC/Laxus — `.gitattributes`; личные пути не переносить в общие файлы.
- Не утверждай, что UI/мультиплеер проверены в игре, по одной компиляции или статическим тестам.
- Объекты предметов/способностей 2026-10-18 (Kusanagi, Hashirama Cells, Shun Shun Rikka, Ashisogi Jizo,
  Takaoni, Laxus G AS…) уже в `object-data/` + `.object-data-raw/`; их генератор — `tools/stage_items_2026_10_18.py`
  (идемпотентный, id в `object-data/items-2026-10-18-ids.json`). Иконки и копии эффектов лежат готовыми в
  `assets/ReplaceableTextures/` и `assets/effects/`; BUILD MAIN ставит их сам (`tools/install_project_assets.py`).
  Пересборка иконок — `tools/build_item_icons.py`, эффектов — `tools/build_kusanagi_effects.py`.

## Поддержание памяти

- Changelog-файлы пиши только на английском языке. Только изменения для сообщества: без служебных сведений о сборке, проверках и обновлении описаний/баффов.

- Используй указатели и проверяй затронутый код. Повторный аудит — при смене архитектуры
  или противоречии; не загружай всю документацию сразу.
- После значимой смены контрактов/путей/проверок обнови соответствующий существующий документ.
  Долговечное решение или нетривиальное исправление сохраняй там либо в `docs/ai/KNOWLEDGE.md`:
  причина → решение → источник/проверка → ограничения. Сначала ищи прежнюю запись и обновляй её.
- Не сохраняй переписку, временные задачи, полные логи и мелкие правки. Прогресс UI —
  в существующих UI-документах; не создавай вторую архитектуру/журнал.
- `CLAUDE.md` и `.claude/` сохраняй; их Auto Memory не является памятью Codex.
  Память Codex здесь — файлы проекта; они актуализируются во время задач, фонового обновления нет.
- Работай последовательно; не запускай подагентов без конкретной необходимости и разрешения.
  Экономь чтение/вывод, сохраняя полноту необходимых исправлений и проверок.

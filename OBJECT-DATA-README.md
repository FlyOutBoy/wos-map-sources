# Редактирование объектов Warcraft III в VS Code

Проект читает нативные объектные файлы папки-карты и создаёт компактные JSON-файлы. После проверки изменения записываются обратно в исходные `.w3a/.w3u/.w3t/.w3h/.w3q/.w3b/.w3d` и соответствующие `war3mapSkin`-файлы. Сборка карты в один `.w3x` не выполняется.

## Рабочие файлы

| Файл | Данные |
| --- | --- |
| `object-data/abilities.json` | способности |
| `object-data/units.json` | юниты |
| `object-data/items.json` | предметы |
| `object-data/buffs.json` | баффы и эффекты |
| `object-data/upgrades.json` | улучшения |
| `object-data/destructables.json` | разрушаемые объекты |
| `object-data/doodads.json` | декорации |

Объект находится прямо по своему Warcraft ID. Внутри нет `field_id`, типа, секции, указателя и адреса в бинарном файле:

```json
"A000": {
  "name": "Hoyoverse Raiden Ei Q",
  "base_id": "ANcl",
  "mana_cost level 1": 100,
  "mana_cost level 2": 100,
  "cooldown level 1": 15.0,
  "cast_range level 1": 1400.0,
  "target_type level 1": "Unit or Point Target",
  "options level 1": "Visible"
}
```

Менять нужно только значения после двоеточия. ID объекта и `base_id` являются структурными и защищены от случайного изменения. Числа желательно записывать без кавычек; строки `"150"` и `"12.5"` также корректно преобразуются в числа при сохранении.

В способностях показаны поля, отмеченные на снимках World Editor: иконки, уровни и требования, раса, горячие клавиши, имя, подсказки, Base Order ID, Follow Through, Options, Target Type, область действия, дальность, перезарядка, мана и допустимые цели. Дополнительно сохранены доступные баффы, эффекты, модели эффектов и attachment-поля. В остальных разделах все реально переопределённые в карте значения представлены в таком же компактном виде.

## Работа в VS Code

1. Запустите задачу **WOS Objects: 1. Export map to editable JSON**, чтобы перечитать карту.
2. Откройте нужный файл в `object-data`, найдите ID или имя и измените значения.
3. Запустите **WOS Objects: 2. Validate editable JSON**.
4. Закройте World Editor и запустите **WOS Objects: 3. Save JSON into map folder**.
5. Снова откройте или перезагрузите папку-карту в World Editor.

Повторный экспорт не затирает несохранённые изменения молча. Перед записью изменяемые бинарные файлы копируются в `object-data-backups/<дата_время>/`, а запись выполняется атомарно.

Если после экспорта карта была сохранена в World Editor, задача сохранения автоматически объединит более новые данные редактора с изменениями JSON. Запускать принудительный экспорт и терять JSON-правки не требуется. Если World Editor и JSON изменили одно и то же поле по-разному, сохранение остановится и назовёт конфликтующее поле; до устранения конфликта карта не перезаписывается.

## Служебные данные

Точные типы, rawcode полей, уровни, data pointer и адреса хранятся отдельно в `.object-data-raw`. Редактировать эту папку вручную не нужно. Благодаря ей скрытые поля не удаляются и возвращаются в правильный нативный файл.

Задача **WOS Objects: Prove lossless binary round-trip** ничего не записывает в карту и проверяет, что все 14 поддерживаемых файлов после чтения и кодирования совпадают с оригиналами побайтно.

JSON показывает значения, которые действительно записаны как переопределения в объектных файлах карты. Унаследованные стандартные значения Blizzard, отсутствующие в `.w3*`, World Editor подставляет из игровых SLK-таблиц.

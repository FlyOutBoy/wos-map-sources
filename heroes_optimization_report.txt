ПРОБЛЕМА #1: УТЕЧКА ГЛОБАЛЬНОЙ ТАБЛИЦЫ СТРОК (S2R(R2SW))
--------------------------------------------------------------------------------
Встречается у 26 из 32 героев.
Типичный код:
    set r = r + 0.03
    set r = S2R( R2SW( r , 0, 3 ) )

В чем причина проблемы:
В JASS вещественные числа накапливают погрешность IEEE 754 (0.03 + 0.03 != 0.06).
Чтобы обойти это, автор конвертировал число в строку с 3 знаками через R2SW,
а затем парсил обратно через S2R.
НО: движок Warcraft III добавляет каждую сгенерированную строку в общую
таблицу строк (String Table), которая НИКОГДА не очищается сборщиком мусора!
При вызове 33 раза в секунду каждым героем за матч генерируются сотни тысяч
строк, что приводит к раздуванию оперативной памяти и прогрессирующим фризам.

Решение:
Перейти на целочисленный счетчик тиков:
    set ticks = ticks + 1
    // Например, вместо проверки r == 0.75 проверять:
    if ticks == 25 then // 25 * 0.03 = 0.75


ПРОБЛЕМА #2: ПОСТОЯННАЯ УТЕЧКА BOOLEХPR (Condition(function NoDecor_Filter))
--------------------------------------------------------------------------------
Встречается у 14 героев (Alucard, Akainu, BazzB, Laxus, Toji, Neuvillette, Asta, Brandish и др.).
Типичный код:
    call GroupEnumUnitsInRange(g, x, y, aoe, Condition(function NoDecor_Filter))

В чем причина проблемы:
Вызов Condition(...) создает НОВЫЙ хэндл типа boolexpr в памяти.
Если этот вызов находится внутри таймера 0.03s, спелл порождает 33 новых хэндла
в секунду. Движок WC3 имеет жесткий лимит в 65,536 хэндлов (Handle Table Limit).
Превышение этого лимита приводит к немедленному крашу игры (Fatal Error).

Решение:
Объявить один раз глобальную переменную и переиспользовать ее:
    globals
        private boolexpr NoDecor_Cond
    endglobals
    // В InitXxxSpells:
    set NoDecor_Cond = Condition(function NoDecor_Filter)
    // В перечислении:
    call GroupEnumUnitsInRange(g, x, y, aoe, NoDecor_Cond)


ПРОБЛЕМА #3: БАГ MUI SWAP-AND-POP (ПРОПУСК ТАКТА ДЛЯ ИНСТАНСОВ)
--------------------------------------------------------------------------------
Встречается у 15+ героев (Natsu, Barragan, Okarun, Milim, BazzB и др.).
Типичный код:
    set m_HeroQ[i] = m_HeroQ[MUI_HeroQ]
    set MUI_HeroQ = MUI_HeroQ - 1
    call deallocate(this)
    endif
    set i = i + 1

В чем причина проблемы:
Когда инстанс в слоте `i` завершается, на его место перемещается последний
активный элемент массива `MUI_HeroQ`. Но следующая строка `set i = i + 1`
безусловно увеличивает счетчик. В результате только что перемещенный инстанс
пропускает свою обработку на текущем тике таймера (пропуск кадра движения/урона).

Решение:
Добавить компенсацию индекса:
    set m_HeroQ[i] = m_HeroQ[MUI_HeroQ]
    set MUI_HeroQ = MUI_HeroQ - 1
    call deallocate(this)
    set i = i - 1
    endif
    set i = i + 1


ПРОБЛЕМА #4: НАГРУЗКА НА CPU ОТ StringHash("...") И OrderId("...") В ТАЙМЕРАХ
--------------------------------------------------------------------------------
Встречается у ВСЕХ 32 героев.
Типичный код:
    if LoadInteger(hs, GetHandleId(c), StringHash("mode g")) == 1 then
    if GetUnitCurrentOrder(c) == OrderId("smart") then

В чем причина проблемы:
Функция StringHash выполняет посимвольное полиномиальное хэширование C++ строки
на каждом вызове. В таймере 0.03s для 10-15 ключей это десятки тысяч операций
хэширования в секунду. Заказы OrderId("smart") также выполняют строковый поиск.

Решение:
Объявить константы в начале файла:
    globals
        private constant integer HASH_MODE_G = StringHash("mode g")
        private constant integer ORDER_SMART = 851971
        private constant integer ORDER_MOVE  = 851986
    endglobals


ПРОБЛЕМА #5: ФРАГМЕНТАЦИЯ ТАБЛИЦЫ ХЭНДЛОВ (CreateGroup / DestroyGroup)
--------------------------------------------------------------------------------
Встречается у ВСЕХ 32 героев.
Каждый спелл при старте вызывает CreateGroup(), а при завершении DestroyGroup().
При интенсивном бое это приводит к тысячам созданий/удалений хэндлов групп,
фрагментируя внутреннюю память WC3.

Решение:
Для синхронных FirstOfGroup-циклов перечисления использовать одну статическую
глобальную группу:
    globals
        private group ENUM_GROUP = CreateGroup()
    endglobals

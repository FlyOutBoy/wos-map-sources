## Найденные причины

- `SaveSystem_Init` не запускал чтение. `SaveSystem_InitLoad` был пустым.
  Загрузка происходила при открытии Career и перед сохранением результата.
- `WCS_UpdateHome` запрашивал games/wins для `viewer = null`. Присваивание
  `Player(pid)` происходило позже, поэтому главная страница показывала нули.
- Повторное чтение перед записью могло возвращать старое содержимое из кеша
  Preloader. Повторное чтение теперь не используется для накопления результата.
- Проверки исходного имени учитывали пустую строку без явной проверки null;
  резервные ключи включали номер слота. Это устранено.
- Повторное событие окончания уже записанного матча могло добавить ещё одну игру.
- В первоначальных файлах имя владельца не хранится открытым текстом. Найдены
  три local4-файла с разными ключами и одной игрой каждый. По одному имени файла
  нельзя доказать, что все три принадлежат одному игроку, поэтому они не сложены.
- API приложения ограничивает запрос героя 50 последними матчами и 25 лидерами.
  Отдельного доступного полного профиля игрока не обнаружено. Нельзя считать
  произвольную recent-выборку полной историей за всё время.

## SaveLoad.j: стартовая загрузка и сохранение

- Идентичность фиксируется до удаления BattleTag/VIP-оформления из отображаемого
  имени. Общий startup timer с задержкой 0.10 секунды создаётся и уничтожается
  одинаково на всех клиентах; файл читает только локальный игровой слот 0–9.
  Наблюдатели не читают профиль игрового слота.
- Профиль читается один раз за запуск карты. Открытие Career и окончание матча
  используют уже загруженные значения. Fallback загрузки остаётся идемпотентным.
- Конец матча прибавляет games/wins и статистику героя к локальному кешу и
  перезаписывает один постоянный файл. Повторное событие не удваивает результат.
- Исходный tooltip восстанавливается до разбора строки. Файл содержит только
  вызовы tooltip natives и не вызывает функции карты во время Preloader.
- Проверяются число целых полей, каноническая запись каждого числа, checksum,
  заголовок, допустимые счётчики и конец данных. Повреждённый профиль не применяется
  частично и не заменяется новой карьерой из одной игры.
- Формат локального файла сохраняет `WOS2L5|`, добавляет `V,6|` и завершающую
  запись `E,count,checksum|`. Старые L5 без расширений читаются; новый файл без
  footer отклоняется. Старый парсер способен прочитать A/H/B/I такого содержимого при тех же ключах,
  но старая карта с ключом по BattleTag может искать другой путь.
- Старый `WOS2_local4_0_0.txt` импортируется лишь при отсутствии обычного файла и
  legacy-файла текущего владельца; проверяются все его записи. Нулевой формат
  не содержит доказуемой привязки к нику, это восстановление локального legacy-файла.
- Ошибка локального сейва не останавливает последующий экспорт текущего матча боту.
- Команда `-saveinfo` показывает локальный путь, статус, games/wins, число принятых
  и отклонённых записей, источник приоритетных чисел и путь файла WOSApp.

## Один профиль по одинаковому нику

Согласовано с пользователем: одинакового ника достаточно; доказательство
владения аккаунтом не требуется. Цвета `|cXXXXXXXX`/`|r`, суффикс `[VIP]`, часть
после `#` и внешние пробелы убираются. Ник приводится к нижнему регистру.
`Owner`, `OWNER#1234` и `Owner [VIP]#9876` используют один новый путь независимо от слота.
Настоящее переименование создаёт другой профиль.

Ключи:

```
A = StringHash("WOS2:LOCAL4:A:" + normalizedNickname)
B = StringHash("WOS2:LOCAL4:B:" + normalizedNickname)
```

При редком нулевом hash используются 19001/29001. Локальный путь:
`save\WOS2_local4_<A>_<B>.txt`.

Сначала читается путь по нормализованному нику. Если его нет, проверяется прежний
путь по полному текущему исходному имени, с его старыми checksum-ключами. После
валидного импорта следующий матч записывается в путь по нику; старый файл остаётся.
Если постоянный файл уже есть, legacy-файлы повторно не прибавляются.
Файлы от неизвестных старых тегов автоматически не суммируются: невозможно
отличить независимую историю от копии одного и того же прогресса.

## WOSApp: автоматический экспорт

Добавлен `CareerProfileExport.cs`.

- После сохранения ника в Statistics/Leaderboard сохраняется прежнее значение
  `AppSettings.PlayerNickname`, затем в фоновом потоке создаётся/обновляется
  файл `Documents\Warcraft III\CustomMapData\save\WOS2_app1_<A>_<B>.txt`.
- При запуске приложения запускается фоновое обновление раз в 60 секунд для
  сохранённого ника. Закрытие окна статистики не останавливает этот сервис.
  При закрытии приложения таймер освобождается.
- Путь определяется через Windows MyDocuments, включая штатное перенаправление
  Documents. Он намеренно не зависит от альтернативной папки мониторинга отчётов:
  карта читает CustomMapData/save. Сама карта не пишет app1-файл.
- Используется общий кеш HeroStatsSharedCache, затем фоновое обновление API.
  Файл создаётся сразу из имеющихся данных; при отсутствии истории создаётся
  корректный нулевой файл. Такой файл не перекрывает локальную карьеру.
- Для каждого героя используются доступные итоги соответствующего ника из
  `windows.all.topPlayers`, без выбранного фильтра версии/даты интерфейса.
  Варианты одного ника с разными тегами объединяются.
- Увиденные завершённые матчи дополнительно накапливаются в отдельном журнале
  `%LOCALAPPDATA%\WOS2 App\career\WOS2_app1_<A>_<B>.txt.json`.
  MatchId предотвращает повторный учёт одного матча. Уход старого матча за окно
  recentLimit не удаляет уже накопленную запись.
- Журнал хранит базовые агрегаты и число наблюдавшихся матчей на момент получения
  агрегата. Если игрок позже исчез из списка лидеров, новые увиденные матчи
  прибавляются к этой базе; уже включённые в базу матчи повторно не прибавляются. Отстающий серверный
  агрегат не уменьшает уже накопленное число игр.
- При отсутствии серверного агрегата и старой базы учитываются только реально
  увиденные матчи. Поэтому ранее не наблюдавшаяся история игрока вне top25 может
  отсутствовать. Нужен полный endpoint игрока для гарантированно полного итога.
  Эта интеграция такой endpoint на сервере не создаёт.
- Общие app-games/app-wins — сумма доступных счётчиков по героям. Винрейт
  вычисляет карта, отдельных округлённых процентов в файле нет.
- Запись через временный файл и File.Replace/File.Move; неизменное содержимое
  не переписывается. Сначала проверяются размеры и счётчики. Повреждённый журнал
  не обнуляет существующий экспорт. Пустой ник не создаёт файл.
- В интерфейсе есть локализованные состояния экспорта на RU/EN/UA. Фоновая ошибка
  записывается в `%LOCALAPPDATA%\WOS2 App\career-export-error.txt`; это последняя
  ошибка с временем, а не индикатор текущего состояния.

## Формат WOSApp и приоритет в карте

Компактный payload:

```
WOS2APP1|A,games,wins,checksum|H,heroRawcode,games,wins,checksum|...|E,count,checksum|
```

Экспорт — исполняемый Preloader-файл с функцией PreloadFiles, простыми вызовами
BlzSetAbilityTooltip и PreloadEnd. Используются 10 стандартных способностей
`Amls, Aroc, Amic, Amil, Aclf, Acmg, Adef, Adis, Afbt, Afbk`, по 240 ASCII-символов.
Максимум 2400 символов payload, 48 героев, 10 000 000 общих игр. Пределы проверяются
до публикации, без молчаливого обрезания.

C# реализует SStrHash2/lookup2 Jenkins с 32-битным переполнением и нормализацией
Warcraft. C# GetHashCode не используется. Проверяется привязка к ключам ника,
checksum каждой записи, footer, отсутствие повторных героев и совпадение общей
суммы с героями. Это проверка соответствия файла нику и целостности, не авторизация
аккаунта. Unicode зависит от нормализации конкретной версии Warcraft; ASCII и
реальные ключи текущего игрока проверены. Кириллица требует проверки в игре.

Карта читает app1-снимок после локального профиля в том же startup callback.
Все 10 исходных tooltips возвращаются до разбора. Данные остаются исключительно
локальными; нет BlzSendSyncData и изменения игрового состояния.

- Валидный непустой WOSApp имеет приоритет для общих games/wins и имеющихся героев.
- Пустой, отсутствующий, повреждённый или чужой файл даёт fallback на локальный.
- Герой, которого нет в app-снимке, показывает собственные локальные метрики.
- Список сохранённых героев объединяет оба источника без повторов.
- Локальная карьера продолжает накапливаться независимо и отображается отдельной
  строкой: games и локальный winrate. App и local не складываются из-за перекрытий.
- Раунды, combat-метрики, best и предметы остаются из локальной карьеры.
- Даже при ошибке локального файла валидный app-снимок можно показать; повреждённый
  локальный файл сохраняется и не перезаписывается.

Добавлены API: SaveSystem_HasAppProfile, SaveSystem_CareerSource,
SaveSystem_HeroCareerSource, SaveSystem_GetLocalGames/Wins,
SaveSystem_GetLocalHeroGames/Wins, SaveSystem_AppFilePath и внутренний parser.
Существующие личные getters выбирают приоритетный источник; совместимые global
getters по-прежнему локальные. Их не следует использовать для gameplay.

## Исследование и ограничения актуальности

- [FileIO — TriggerHappy](https://www.hiveworkshop.com/threads/fileio.307568/):
  короткие tooltip carriers, чтение после Preloader, возвращение исходных tooltip.
- [Пример startup timer](https://xgm.guru/p/wc3/preloadinref): загрузка при старте
  и пути внутри CustomMapData.
- [SStrHash2 — LeP](https://www.hiveworkshop.com/threads/bits-of-interest.213272/):
  алгоритм StringHash и нормализация ASCII/слешей.
- [Документация StringHash](https://lep.nrw/jassbot/doc/StringHash): нормализация
  и различия Unicode между версиями Warcraft.
- [Сообщения о кеше Preloader](https://www.hiveworkshop.com/threads/codeless-save-and-load-multiplayer-v3-0-1.278664/page-8):
  в некоторых клиентах повторно читается первый снимок по тому же пути.
- [Локальный Preloader и desync](https://www.hiveworkshop.com/threads/desync-when-calling-preloader-locally.360261/):
  данные диска нельзя переносить в игровой state без синхронизации.

Приложение обновляет один и тот же файл на диске; карта имеет приоритетный reader
при старте. Это не гарантирует немедленное перечитывание обновлённого файла уже
работающим Warcraft. Для проверки свежего снимка сохранить ник/дождаться обновления
в WOSApp, затем полностью перезапустить Warcraft. Обход кеша живого клиента не заявлен.
Гарантия полного исторического итога любого ника также требует полного endpoint
игрока на сервере; текущая интеграция сохраняет и накапливает доступные данные.

## Ручной перенос и проверка в игре

1. Перенести актуальные SaveLoad и UI CAREER в карту. Save2 и RoundEnd не менять.
2. Запустить WOS2 App 5.0.14 Preview, указать игровой ник и нажать сохранение в
   Statistics/Leaderboard. Дождаться сообщения о сохранённом файле. Фильтры
   интерфейса не должны влиять на экспорт. Файл лежит в CustomMapData/save.
3. Полностью перезапустить Warcraft, запустить карту и выполнить `-saveinfo`.
   При непустом валидном app-профиле источник должен быть WOSApp. Career показывает
   его games/winrate и отдельные local-games/local-winrate.
4. Завершить матч: локальный файл по нормализованному нику должен получить +1 игру
   и при победе +1 wins. При миграции старый файл остаётся, новый путь виден в -saveinfo.
5. После завершения клиента временно убрать app-файл и снова запустить карту:
   приоритетные числа должны совпасть с накопленной локальной карьерой.
6. Проверить тот же ник с другим регистром/#тегом и слот: постоянный новый путь
   остаётся тем же. История от неизвестного старого тега сама не суммируется.
7. Проверить два реальных клиента с разными профилями и наблюдателя: локальные
   числа различаются, gameplay совпадает, desync отсутствует, бот получает прежний
   отчёт текущего матча.
8. Отдельно проверить обновления без перезапуска Warcraft, кириллицу и 48 героев:
   это проверки реального движка, не результаты mock-тестов.
